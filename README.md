# HireMeBot — Frontend

Mobile-first React PWA for the HireMeBot student authentication and onboarding
flow. Built with Vite, TypeScript, Tailwind CSS, Radix primitives, and
TanStack Query. The authentication layer runs against a **mock** service
today; the Cognito/backend integration boundary is scaffolded and documented
in [`docs/BACKEND.md`](docs/BACKEND.md).

## Quick start

```bash
npm install
npm run dev
```

Then open http://localhost:5173.

The signup → OTP → Google → success → dashboard flow works end-to-end against
the in-browser mock service.

### Dev credentials for the mock flow

- **OTP code**: `123456`
- All other state is simulated in `localStorage` under the `hmb.mock.*` keys.
- Clear the keys (or call "Sign out") to start over.

## Theming

- Themes: `light`, `dark`, and `system` (default). The chosen value persists
  in `localStorage` under `hiremebot-theme`.
- The initial theme is applied synchronously in `index.html` to avoid a flash
  of the wrong theme on first paint.
- Colors are defined as HSL CSS variables in `src/styles/globals.css` and
  consumed through Tailwind tokens — no hardcoded hex values in components.

## Mobile & PWA

- Viewport is `width=device-width, initial-scale=1, viewport-fit=cover` with
  safe-area padding utilities (`.safe-top`, `.safe-bottom`).
- Bottom navigation only appears on authenticated student routes.
- Service worker is generated by `vite-plugin-pwa` with `registerType:
  autoUpdate`. **It never caches API responses or JWTs** — `/api/*` and
  `/auth/callback` are in the `navigateFallbackDenylist`, and no runtime
  caching rule targets authenticated requests.
- Install prompt is handled by the browser; valid icons at 192/512 and a
  maskable 512 variant are generated by `scripts/generate-icons.mjs`.

## Authentication boundary

Everything flows through the `AuthService` interface in
[`src/features/auth/types.ts`](src/features/auth/types.ts). Two
implementations exist:

- `MockAuthService` — fully functional for frontend development. The accepted
  OTP is `123456` and all state lives in `localStorage` under `hmb.mock.*`
  keys. Clearly marked as development-only.
- `CognitoAuthService` — scaffold with explicit `notConfigured` errors. See
  [`docs/BACKEND.md`](docs/BACKEND.md) for the required Cognito + backend
  configuration before switching.

`src/features/auth/AuthProvider.tsx` wires the chosen implementation into the
React tree; swap the `authService` constant when real APIs ship.

## Testing

```bash
npm run test
```

Vitest + React Testing Library covers:

- `signupSchema` validation (names, terms, phone normalization)
- `MockAuthService` happy path, OTP rejection, resend throttle, activation gating
- `OtpInput` typing, paste, non-numeric filtering, `onComplete`

- `ThemeProvider` dark class + persistence
- Route guards redirecting unauthenticated / incomplete-onboarding traffic

## Student Dashboard V1

Student-facing screens (all under `/student/*`, mock data only):

- `/student/dashboard` — greeting header + month card + Monthly/Today's
  progress + 4-up statistics (Applications card deep-links to the list;
  In Review/Interviews/Offers open a shared `ComingSoonDialog`) + Weekly
  Activity SVG bar chart + Recent Applications
- `/student/applications` — search + status filter chips with real counts +
  application list sorted newest-first + empty state
- `/student/applications/:id` — company header + current-status banner +
  status timeline + Job Details grid + not-found state
- `/student/profile` — personal info from the mock auth user + Account &
  Settings list (Theme cycles System → Light → Dark, Edit opens coming-soon)
- `/student/notifications` — All / Application Updates / System tabs, each
  rendering a tab-specific empty state (no fake notification records)

### Targets math

`src/features/student/lib/targets.ts` provides:

- `countWeekdaysInMonth(year, month)` — pure local-calendar weekday count
- `computeDailyTarget(date, submittedToday)` — target 50 on weekdays, 0 on
  weekends; `remaining = max(0, target − submitted)`; percent clamped to 100
- `computeMonthlyTarget(year, month, submittedThisMonth)` — target =
  weekdays × 50

Unit-tested across Oct 2026, Feb 2024 (leap), Feb 2025, and over-target cases.

### Mock data

- `MOCK_APPLICATIONS` in `src/features/student/data/mockApplications.ts` is a
  **representative subset** that drives the Applications list, Recent
  Applications, and Application Details screens.
- `MOCK_DASHBOARD_SUMMARY` in the same file provides the aggregate dashboard
  numbers (820 submitted this month, 126 in review, 8 interviews, 2 offers,
  weekly bar values). These are documented as sample preview values — the
  sample list is **not** the full 820-record dataset.
- Preview tiles (In Review / Interviews / Offers) are marked "Preview" and
  open `ComingSoonDialog`. They never navigate.

## What is **not** implemented (yet)

- Real Cognito or backend API calls — the implementation stops at the
  `AuthService` and `studentService` boundaries. See `docs/BACKEND.md`.
- Live notifications (no polling / WebSocket / push). Bell navigates to the
  future-release Notifications page per the V1 spec.
- Profile editing (Edit opens a coming-soon dialog).
- Real interview, offer, or review tracking (preview placeholders only).
- Recruiter and Manager experiences (restricted — not part of this phase).
- Email/password signup, forgot-password, and email OTP (intentionally out of
  scope per spec).

See [`docs/BACKEND.md`](docs/BACKEND.md) for the full list of backend
dependencies and Cognito configuration still required.
